How to organize a folder full of backing tracks

macOS 14+ · free beta

One song, one folder. The backing track, the tab and the notes about the song live inside that folder, and an index sits on top so you can search the collection and reorder it into setlists. That is the whole idea. Grouping by file type — all audio in one folder, all tabs in another — is the thing that makes a collection unusable, because playing one song means touching three places.

Why the mess happens

It is never laziness. Backing tracks arrive from everywhere: a purchase here, a download there, a rip from a video, a file a bandmate sent. Each one lands wherever that app defaults to, gets whatever name the source gave it, and is filed by nothing. After two years you have a Downloads folder with yt-dlp-2019.mp3 next to backing_final_v2_REAL.mp3, a separate folder of PDFs, and a browser bookmark for the version you actually liked. The songs are all there. You just cannot start playing.

Four rules that actually fix it

  1. One song, one folder. Everything about that song goes in. Different versions are different folders or clearly marked files inside it, never loose copies in three places.
  2. Keep the tab with the audio. The moment the sheet lives somewhere else, you stop opening it. Audio, PDF, Guitar Pro file and lyrics belong side by side.
  3. Record where the hard part is. The one piece of information a folder cannot hold is that the solo starts at 1:42 and the last four bars are the problem. Write it down once, where the song is.
  4. Put an index on top, not inside the files. Search, favourites, setlists and practice history should be a layer over the folder — so reorganising never means renaming files.

About naming conventions

A consistent name such as Artist - Title (version).ext is worth having, but understand what it buys you: it makes files sort predictably and survive a move. It does not give you a library. You cannot search a filename convention for the song you were working on last week, you cannot reorder it into a setlist without touching every file, and the moment two people name things differently the convention collapses. Names are for humans reading a folder; the index is for everything else.

How JamCrate does it

  • Drop a whole folder, not one file at a time. Point it at the mess you already have. It pairs each backing track with the matching tab by name — ignoring noise words like backing, minus, final — and asks only when the pairing is genuinely unclear.
  • It copies files into a managed library at ~/Music/JamCrate, one folder per artist and song. Your originals are not moved or modified, and the library does not depend on files scattered across the disk.
  • The whole folder is the library. Move it to another disk, a USB stick or a Mac: ⌘, points JamCrate at the new location and everything — songs, markers, setlists, rigs — comes with it.
  • Markers, links and notes ride with the song. The YouTube original you learned from, a lyrics page, a capo reminder, and the In/Out markers around the solo are stored next to the song, not in a separate notes app.
  • Setlists are a view, not a copy. Put songs in playing order for a rehearsal or a gig without duplicating a single audio file.

Backups: one archive beats a synced folder

If your library lives in a cloud-synced folder, a half-finished sync is a library with missing files, and version history is whatever the provider decides to keep. JamCrate writes the entire library — tracks, tabs, markers, setlists and rigs — into a timestamped .jamcrate.zip in a Backups folder, verifies the archive before reporting success, and can re-verify any older version later. Each backup is a self-contained file you can put on a USB stick or send to another machine, and a restore brings every song back complete or not at all.

Questions

Will importing copy my files or move them?

It copies. Your originals stay exactly where they are, which means you can try it on a real folder without risking anything.

What if a song has three different versions?

Keep them as separate songs or separate files in one song folder. Marking the solo is what makes one version the practice version — the others can stay as references.

Does it work without an internet connection?

Yes. There is no account and no cloud storage; the library is a folder on your disk. Internet is only needed for the optional video-link import.
